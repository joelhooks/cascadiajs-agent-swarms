# Talk Prep Resource Map

Purpose: collect high-quality resources adjacent to Gary Bernhardt's Deconstruct article on preparing a talk.

## A-tier resources

### Deconstruct: How to Prepare a Talk

URL: https://www.deconstructconf.com/blog/how-to-prepare-a-talk

Why it matters: best process resource found so far. Treats talks as spoken performances discovered through repeated out-loud rehearsal, not slide-writing exercises.

Use for CascadiaJS: default process. First spoken run before outline/slide polish.

### speaking.io — Zach Holman

URL: https://speaking.io/

Useful sections:

- https://speaking.io/prep/practicing-it/
- https://speaking.io/prep/recording-your-talk/
- https://speaking.io/react/improving/
- https://speaking.io/deliver/your-voice/
- https://speaking.io/prep/live-tech-demos/
- https://speaking.io/plan/repetition/
- https://speaking.io/plan/talks-are-entertainment/

Why it matters: practical, developer-native, broad coverage from planning through post-talk iteration. Strong complement to Deconstruct: less philosophical, more tactical.

Key points:

- record yourself; listen for filler and weak pacing
- talks are stories/entertainment, not academic dumps
- repetition is a feature, not a bug
- use Q&A and hallway questions as feedback signals
- improve sections where audience attention drops

Use for CascadiaJS: delivery/design/recovery checklist after spoken shape exists.

### Zach Holman: Slide Design for Developers

URL: https://zachholman.com/posts/slide-design-for-developers/

Why it matters: still one of the best developer slide-design resources. Opinionated enough to be useful.

Key points:

- huge text; then remove half the words and make it bigger
- design for people three rooms away
- slides support spoken words; they are not standalone documents
- color/contrast first
- repetition and recap slides help memory
- letters/words can be visual shapes

Use for CascadiaJS: slide design once the spoken talk stabilizes. Especially useful for cartridge/party/permadeath motif slides.

### Zach Holman: The Talk on Talks / making-of

URLs:

- https://zachholman.com/talk/the-talk-on-talks/
- https://zachholman.com/posts/the-video-of-the-talk-on-talks
- https://www.youtube.com/watch?v=YVb2GsJHejo

Why it matters: meta-talk plus behind-the-scenes creation process. Good for seeing how a talk about talks is itself structured.

Use for CascadiaJS: steal the 3-part structure discipline if this talk starts sprawling.

## B-tier / useful but less canonical

### What I wish someone told me about speaking at tech conferences

URL: https://dev.to/tlakomy/what-i-wished-someone-told-me-about-speaking-at-tech-conferences-3opp

Useful for:

- practice out loud, standing up
- don't stop/restart after mistakes; recover like you would on stage
- demos need offline/backups/video

Use for CascadiaJS: demo contingency plan.

### How to prepare your tech speech

URL: https://tereza-tizkova.medium.com/how-to-prepare-your-tech-speech-e21a090e3f30

Useful for:

- recording practice
- real-person feedback
- question handling strategy
- audience engagement
- timing and iteration goals
- practicing with big screen / equipment

Use for CascadiaJS: final-week rehearsal checklist.

### Practicing and Nailing My First Conference Talk

URL: https://dev.to/integerman/preparing-and-nailing-my-first-conference-talk-25jd

Useful for:

- first-talk field report
- intro practice as on-ramp into flow
- room/equipment prep
- disaster cheat sheet
- slide timing gotcha

Use for CascadiaJS: operational talk-day checklist, not content design.

### Reddit: Giving technical talks

URL: https://www.reddit.com/r/ExperiencedDevs/comments/rcjs9m/giving_technical_talks/

Useful for blunt practitioner advice:

- rehearse standing up and projecting
- don't look at slides
- minimal text
- tailor to audience
- start with a problem statement
- explain like a whiteboard conversation with people who lack context

Use for CascadiaJS: sanity check against over-intellectualizing.

## Resources rejected / low signal

- Generic “tech conference speaking tips” SEO posts: mostly listicles; not worth using as doctrine.
- Random slide-deck design tips: useful but weaker than Holman unless a specific visual style problem emerges.

## Current synthesis for this talk

Use Deconstruct for process, speaking.io for tactics, Holman slide design for visuals.

Recommended sequence:

1. Spoken raw pass from current thesis.
2. Capture note slides only.
3. Repeat once/day until high-energy sections emerge.
4. Apply rule-of-three / 4–6 section structure.
5. Cut to 25 minutes.
6. Design slides with huge text, motifs, repetition, and staged reveals.
7. Record one late rehearsal.
8. Prepare demo failure path.

Anti-pattern to avoid: turning the CascadiaJS repo into a research museum. The talk has to become a performed idea, not an evidence pile.
